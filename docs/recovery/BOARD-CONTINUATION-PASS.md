# Continuing the board without resetting machine state

15 October 2026. Live diagnostics now offers **Continue into the next board
selection / verified result**, enabled by default. The choice applies on Start
feature or Restart. Disable it to retain the earlier one-advance/link boundaries.
The headless session exposes the same explicit `continueBoard` option, defaulting
to false for compatibility with bounded reference callers.

A demonstrated Live path rolls from square 32 to 36, returns through the actual
DE75/DDAF frames to DD38 and accepts another physical START. VM memory, RNG,
timers, motor state, board history, nudge pot and accounting remain in the same
session. No reset, saved-state replacement or recorded input/outcome substitution
occurs between selections. This is a repeatable board fragment, not persistent
whole-machine play or a complete implementation of every board result.

## Live behaviour and explicit boundaries

The recovered VM handles the DE81 snake boolean, DE96 return, E43D type read and
DDAF repeat-selection branch. Live now resets its diagnostic selection/movement
flags when DD38 executes, instead of treating it as a fatal boundary. It marks
the temporary panel interactive only after reaching the actual DD4E input loop.
The last completed dice request remains visible while the next prompt executes;
preparing a new roll replaces it through the existing motor path.

Physical START still enters through BLACK2 bit 80 and recovered sampling/latch
handling. TAKE remains bit 01. Pause releases held controls and suspends actual
execution/time; Resume preserves state. Restart alone restores initial state.
Board prompt entry count is visible in diagnostics. Verified playback remains a
separate mode and does not use this option.

The natural ladder reaches DD38 at 22, but initializing that prompt requires
native 29F4 best-reel-result search for nudge availability. Live stops explicitly
before that unimplemented helper. It does not assume nudges are available or
return a constant. Static exports show 29F4 saving/restoring symbol words,
allocating a counted scratch frame, calling 2A7F movement-budget search and
returning a signed result. The search depends on 1AC3 result lookup and 6FA2/6FB8
frame semantics. Selected existing exports and a dependency/provenance map are
curated as a next-work baseline, not an implementation or runtime proof.

Live also stops at E2FC for result types other than the already recovered type-2
route. Thus normal rolls reaching type 3 and the snake's type 8 remain explicit
result boundaries. Taken type-2 Skill Cash routing still executes and finishes.
An outer E460 machine return from a natural link entry is separately bounded.
No unrelated feature, award, collection or machine-startup semantics are guessed.

The 32→36 repeated-prompt test uses synthetic player timing applied to actual
physical input handling. Its second roll is generated by the retained machine
state. It is not a natural MAME capture of the full 32→36→next sequence. The natural
references prove the listed caller paths; the Live test proves incremental reuse
and inputs. CPU/IRQ pacing remains the provisional captured adapter, with the
earlier Live polling differences and roll alpha brightness discrepancy unchanged.
No full CPU/scan-time equivalence claim is added.
