COIN ALARM / INPUT HARNESS
John identifies the historical 100P LOCKED ALM as the normal held/stuck 100p coin-switch alarm. SCRIPT-CLASSIFICATION.txt and its report generator now record this explanation. The old 300s run was not used as evidence of a ROM bug or emulator defect; why its harness triggered that state has not been independently isolated.
New runs logged AUX2 every frame: 20 coin pulses, each exactly three frames (50ms) high, with release between pulses; no ALM display sample appeared in these three runs. Port reads reflect an override one frame later than the frame callback that requests it, consistently in discovery and replay.
The initial explore-collect-a run exposed a harness error: floating-point mask keys did not match integer control keys, so some nudge presses never reached MAME. Corrected v2 uses integer-normalized keys and verifies actual input levels. The initial run remains diagnostic and is excluded from coverage and replay claims.
